# PromptCompiler

**Английское описание → JSON сцены → готовый промпт.** GPT-2 124M, дообученная через [nanoGPT](https://github.com/karpathy/nanoGPT), извлекает два объекта, их цвета, материалы и расположение. Интерфейс — Streamlit; сообщения обрабатываются независимо.

**Бизнес-сценарий:** специалист по контенту готовит брифы для предметных рекламных изображений. Он описывает товары, материалы и размещение, проверяет извлечённые поля и копирует единообразный промпт или экспортирует JSON для дальнейшей обработки. Прототип помогает структурировать бриф; генератор изображений подключается отдельно.

## Запуск

Python 3.11, команды из корня проекта. nanoGPT подключён как Git submodule и закреплён на коммите [`3adf61e`](https://github.com/karpathy/nanoGPT/commit/3adf61e154c3fe3fca428ad6bc3818b27a3b8291).

```powershell
git submodule update --init --recursive
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt -r requirements-ui.txt
# CUDA-сборка для NVIDIA:
python -m pip install --force-reinstall "torch==2.11.0+cu128" --index-url https://download.pytorch.org/whl/cu128
```

## Готовая модель

Скачай `nanogpt_v0.4_2_seed42.zip` из [папки с моделью на Google Drive](https://drive.google.com/drive/folders/1i14pX0w8dLZuurViUw_j08cCfrOtjPEO?usp=sharing). Если архив лежит в корне проекта, распакуй его командой:

```powershell
Expand-Archive -LiteralPath .\nanogpt_v0.4_2_seed42.zip -DestinationPath .\experiments
```

Итоговый путь:

```text
experiments/
└── nanogpt_v0.4_2_seed42/
    └── ckpt.pt
```

Не должно быть лишнего вложенного каталога с тем же именем. Для использования готовых весов генерация датасета и обучение не нужны.

Из корня проекта запусти интерфейс и выбери `nanogpt_v0.4_2_seed42`:

```powershell
python -m streamlit run app.py
```

Или вызови модель из Python:

```python
from inference import Model

model = Model(experiment_name="nanogpt_v0.4_2_seed42")
print(model.generate_scene("Show the red ceramic cup next to the blue metal box."))
```

Веса и `.bin` исключены из Git. Инференс автоматически использует CUDA, если она доступна, иначе CPU. При первом запуске может потребоваться интернет для токенизатора.

Проверено 18.10.2026: новая `.venv`, отдельный клон nanoGPT, архив из Drive, запуск Streamlit и один запрос на GPU. [Отчёт проверки](results/clean_environment_check.json).

## Обучение

В `src/finetune.py` выбери `MODEL_VERSION = "v0.4_2"`.

```powershell
python src/create_dataset_v04_2.py
cd nanoGPT
python -u train.py ../src/finetune.py --max_iters=5000 --eval_interval=500
```

Для продолжения существующего checkpoint:

```powershell
python -u train.py ../src/finetune.py --init_from=resume --max_iters=5000 --eval_interval=500
```

`max_iters` — общий предел шагов. Веса сохраняются в `experiments/nanogpt_v0.4_2_seed42/ckpt.pt` с заменой предыдущего checkpoint.

## Результаты

Из корня проекта: `python benchmark.py`. Модели выбираются в `MODELS_TO_COMPARE`, запросы и эталоны — в `tests.json`.

На 50 тестах все модели выдали 50 валидных JSON. Object F1 учитывает имя и свойства объекта; отношения проверяются при полном совпадении сцены.

| Модель | Шаги¹ | ≈ Объём train-потока² | Верные объекты | Object F1 | Правильные сцены |
| --- | ---: | ---: | --- | ---: | --- |
| v0.3 | 200 | 1183,68% (11,84 прохода) | 16/100 | 0,16 | 5/50 — 10% |
| v0.4 | 200 | 1,40% | 52/100 | 0,52 | 23/50 — 46% |
| v0.4_1 | 5000 | 9,84% | 54/100 | 0,54 | 25/50 — 50% |
| **v0.4_2** | **5000** | **10,03%** | **95/100** | **0,95** | **47/50 — 94%** |

¹ Метрики — из последнего запуска benchmark, шаги — из текущих checkpoint. Первые эксперименты использовали параметры `finetune.py` на 200 шагов; результат v0.4_2 получен после продолжения до 5000 шагов.

² Обработанные токены относительно размера `train.bin`, с учётом возможных повторов случайных окон; это не доля уникально просмотренных данных.

Сравнивались расширение словаря, разнообразие фраз, пропуски свойств и увеличение обучения. Бюджеты обучения различаются, поэтому прирост нельзя приписать только данным. Эти 50 запросов использовались при разработке.

### Дополнительная проверка v0.4_2

Отдельный набор `tests_holdout.json` содержит 120 новых запросов. Точных совпадений запросов с текущими обучающими потоками не найдено; совпадение или эквивалентность самих сцен не исключены. [Описание проверки](tests_holdout.md).

```powershell
python benchmark.py --tests tests_holdout.json --models nanogpt_v0.4_2_seed42 --output results/holdout_v042_first.json
```

Результат: **120/120 валидных JSON, 223/240 верных объектов, Object F1 = 0,9292; 71/120 правильных сцен — 59,2%.**

| Группа | Правильные сцены |
| --- | --- |
| Перефразирования | 14/24 — 58,3% |
| Обратный порядок описания | 0/24 — 0% |
| Пропущенные свойства | 20/24 — 83,3% |
| Необычные сочетания | 24/24 — 100% |
| Свободные формулировки | 13/24 — 54,2% |

Основное ограничение — понимание отношений. Во всех 24 случаях обратного порядка модель выдала связь `o1 → o2`, хотя эталон требует обратного направления; в 20 случаях оба объекта извлечены правильно. Это согласуется с устройством обучающих данных, где связь всегда направлена от первого объекта ко второму. Также обнаружены ошибки на синонимах вроде `beneath` и `below`.

Модель хорошо извлекает объекты, но перенос на новые конструкции ограничен. Следующее улучшение — разнообразить направление связей относительно порядка упоминания и формулировки отношений. Если использовать ошибки этого набора для настройки, для финальной оценки понадобится новый тест.
