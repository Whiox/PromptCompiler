# Дополнительная проверка

`tests_holdout.json`: 120 запросов и 240 эталонных объектов, по 24 запроса в группе.

| Группа | Что проверяется |
| --- | --- |
| paraphrases | beneath, beside, underneath, alongside и другие способы описания отношений |
| reversed_order | Сначала назван ориентир, затем объект; направление связи нужно восстановить |
| missing_attributes | Пропуски цвета и материала у одного или обоих объектов; эталон — null |
| unusual_pairs | Необычные сочетания знакомых объектов и материалов |
| free_form | Несколько предложений, перечисления, общее свойство двух объектов, respectively |

Набор составлен ассистентом после разработки моделей; веса при подготовке не менялись. Перед окончательной оценкой желательно независимо просмотреть эталоны. Все примеры остаются в прежней схеме: два объекта разных типов и одно отношение. `in front of` уже есть в обучающем словаре и само по себе не является незнакомым отношением.

Проверены JSON, уникальность ID и запросов, допустимые значения, ссылки и отсутствие точных повторов прежних 50 запросов. Поиск токенизированных префиксов запросов в текущих train.bin v0.3, v0.4, v0.4_1, v0.4_2 нашёл 0 совпадений. Результат проверки, хеш набора и размеры/время изменения checkpoint сохранены в `tests_holdout_audit.json`.

Проверка не исключает совпадения эталонных или эквивалентных сцен с обучением. Это отложенная проверка новых запросов, а не доказательство обобщения на заранее исключённые комбинации. Группы могут содержать разные описания одной сцены.

## Запуск из корня проекта

```powershell
python benchmark.py --tests tests_holdout.json --models nanogpt_v0.4_2_seed42 --output results/holdout_v042_first.json
```

Вывод содержит общий F1 и число правильных сцен по группам. В отчёте сохраняются все запросы, эталоны и исходные ответы. Для следующего запуска выбирай другое имя отчёта: указанный output перезаписывается.

Benchmark теперь нормализует симметричное `next to`, обратные пары under/above, left/right, behind/in front of и перечисленные в коде синонимы. Эквивалентные отношения не должны считаться ошибкой. Для прямого сравнения со старым набором перезапусти и его по новым правилам.

Не используй результаты этого набора для настройки, если представляешь его как финальный тест. Если по его ошибкам меняются данные, параметры или checkpoint, он становится набором разработки; потребуется новый отложенный набор. Первый реальный прогон при подготовке этих файлов не выполнялся.
